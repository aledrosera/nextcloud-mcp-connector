    Normalform und Klassen (29-RESEARCH.md Frage 3):
    - tag_skeleton: unicodedata.normalize("NFKC"), casefold, nur Zeichen mit Kategorie L oder N behalten. "Kein KI" -> "keinki"; "kein_ki" -> "keinki"; "kein" + chr(0x2013) + "ki" -> "keinki"; "kein" + chr(0x2010) + "ki" -> "keinki"; "Kein KI-Training" -> "keinkitraining".

Eigene Distanzfunktion (optimal string alignment, etwa 15 Zeilen), kein Paket.
    - access_of: visible and assignable -> public; visible and not assignable -> restricted; not visible -> invisible.

    Urteil (audit), Schritte immer alle sieben in fester Reihenfolge:
    - Fall "kein Tag" mit admin_checked=True (keine exakte, keine Variante): tag_exists=note "no_tag", folgende Schritte bis auf operating_mode=skipped und assignment_count=skipped; passed=true, mode=none, assigned=0.
    - Fall public exakt, sichtbar, admin_checked: alle passed; mode=self_service; assigned = Summe.
    - Fall restricted mit groups=("ki-verantwortung",): mode=organisation; operating_mode passed; Gruppen im TagFacts erhalten. Restricted mit groups=(): mode=organisation, note "admins_only".
    - Gemischt: ein exaktes public und ein exaktes restricted -> mode=self_service (jeder darf das public-Tag setzen), note "mixed_access".
    - Unsichtbares exaktes Tag bei admin_checked=True: tag_visible=failed, passed=false, mode=misconfigured; dessen Zuordnungen zählen in unprotected.
    - admin_checked=False ohne exaktes und ohne Varianten-Tag: tag_exists=note "no_visible_tag" (nicht "no_tag"), passed=true, mode=none; ein Test pinnt die Notiz, damit die Konsole "no visible kein-ki tag" sagt und nie behauptet, es gebe kein Tag.
    - admin_checked=False: admin_identity=not_checked note "admin_not_named", tag_visible=not_checked note "visibility_not_checked"; unsichtbare Tags kommen in diesem Modus gar nicht an (Aufrufer filtert), das Urteil hängt nur an sichtbaren Tags; passed kann true sein.
    - admin_failed=True (Konto ist kein Admin oder unbekannt): checked=false, passed=false, admin_identity=failed, alle weiteren skipped, tags leer.
    - listing_ok=False: checked=false, passed=false, tag_listing_readable=failed, weitere skipped; nie "kein Tag" (Fehlurteil grün verhindern).
    - Nur Variante ("Kein KI"), kein exaktes Tag: tag_exists=failed, no_variants=failed, passed=false, mode=misconfigured, unprotected = Zuordnungen der Variante.
    - Exakt plus Variante: no_variants=note "variant_beside_exact", passed bleibt true (D-29-10), unprotected = Zuordnungen der Variante.
    - Nur similar neben exaktem Tag: no_variants=passed mit note "similar_name"; similar allein ändert passed nie.
    - assigned=None bei einem exakten Tag (Zählung fehlgeschlagen): assignment_count=failed, passed=false.
    - AuditResult.tags enthält kein Tag der Klasse other; Test mit einem fremden Tag "projekt" belegt das.
